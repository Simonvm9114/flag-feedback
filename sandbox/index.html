US-02 — Activator placement

Three activators are bound on load: one in <nav>, one in <aside>, and one injected into a <div> below. Click each — no JS errors should occur and each activator must stay inside its container.

These are three independent initFeedback instances — a test fixture for US-02 only, not a real integration pattern. In a real host application a single initFeedback call is made once in the app shell (e.g. the layout component), and the same activator and panel are available on every page. Draft persistence across navigation is covered by US-19 (Batch 6).

DevTools check: inspect any activator element — its parentElement must be its original host container, not <body> or a package-owned node.

US-03 — No package styles on activator

DevTools check: select any activator — its style attribute must be absent (or only contain host-set values), and no package-injected class should appear in the Styles panel.

Batch 2 — Feedback panel & composition

US-06 Open panel: Click any activator (nav, sidebar, or div) — the feedback panel must open bottom-right. Confirm it contains a comment textarea, category selector (3 options), "Target element" button, "Start recording" button, and a Submit button. Click the × button — the panel must close. Host links and inputs must remain interactive behind the panel.

US-07 Comment: Type text in the textarea and click Submit (select a category first). The intercepted POST in the log below must contain feedback.text matching what you typed.

US-07 Truncation: Click the button below to fill the comment with 10,001 characters, then submit — feedback.text in the log must be exactly 10,000 characters.

US-08 Category: Open the panel and click Submit without selecting a category — an inline error must appear. Select a category and submit — the POST log must contain feedback.category with the correct value (design-request, feature-request, or bug-fix).

US-20 Draft preservation: Open the panel, type a comment, select a category, then close with ×. Re-open — the comment and category must still be there. Then submit — re-open again and the panel must be blank.

The fetch interceptor at the top of main.ts captures every POST and prints the JSON payload in the log panel below.

Batch 3 — Element targeting

US-09 Activate targeting mode: Click an activator to open the panel. Click Target element — the panel must hide and a dark pill reading "Targeting" must appear bottom-left. Click Done in the pill — the panel must reopen with no error.

US-10 Select element & comment: While in targeting mode, click any card, heading, or input in the dashboard. A blue outline must highlight the element and an element-comment prompt must appear bottom-right. Type a comment and click Add target. You must remain in targeting mode (pill still visible). Click Cancel on a fresh selection — no target is added and you stay in targeting mode. Confirm that clicking the activator button itself does NOT open the prompt.

US-11 Multiple targets & submit: Add three or more element targets, then click Done in the pill. The pill must show "Targeting · N selected" while in targeting mode. Back in the panel, fill a comment, select a category, and submit — the intercepted POST in the log below must contain an elementTargets array with all the targets you added (each with path and comment).

Clicking the activator element itself while in targeting mode must be ignored — no self-referential target should appear.
